# 研究工具选择原则

根据研究对象、证据要求、正确性、安全性和复现需求选择工具。先在研究方案中明确所需能力，再由环境计划选择并验证具体实现。记录选择依据、版本、配置和适用边界；工具可用、程序可运行或结果可重复，均不单独构成安全性或研究结论成立的证据。

## 方法与具体选择的边界

通用指引规定所需能力、判断方式、记录字段和存储路径。实际模型、语言、库、机器、服务、参数和输出格式由每个研究实例选择。常用工具可以保留为可选实现，但不因为已经安装而成为研究必须采用的方案。

研究实例使用以下路径契约；这些路径指本地任务文件，不是公开方法仓库中的研究材料：

| 内容 | 实例内的记录位置 |
| --- | --- |
| 研究对象、主张及安全/评价假设 | `docs/research_spec.yaml` |
| 所需工具能力与约束 | `environment/requirements.yaml` |
| 实际模型、实现工具、绘图方式及选择依据 | `environment/tools.yaml` |
| 调查、资源选择、配置计划、执行与验证 | `environment/selection.yaml`、`environment/plan.md`、`environment/changes.md` 及验证记录 |
| 文稿源文件、输出格式与交付路径 | `paper/output.yaml` |
| 实际实验、图表输入和测量记录 | `results/`，通过实例的证据索引引用 |

运行记录保存所引用配置的版本或哈希及实际生效参数；工具选择变更后重新评估对证据和结论的影响。

## 模型按角色选择

区分写作助手、被评测模型、攻击模型和评判模型。只记录本研究实际需要的角色，角色之间不默认共用同一模型。记录版本或可获得的版本标识、部署/接口方式、提示词与参数的引用，以及供应方未公开的信息。

被评测对象和评价工具要分别核验。模型裁判的分数是测量方法的一部分，需按研究目的验证可靠性并报告限制；不能仅凭助手或裁判模型的判断，把输出认定为攻击成功或安全保证。

## 实现按结论要求选择

区分功能原型、仿真和实际实现，说明实现覆盖与省略的操作，以及能支持的主张。语言和框架应满足所需精度、协议语义、系统行为及测量条件，不统一指定数值库、深度学习框架或编程语言。

原型结果不能自动外推到部署性能。若省略了密码学操作、通信、序列化或网络等待，应明确限定结果范围。真正支持端到端性能主张的实验必须覆盖所声称的成本；局部微基准则标明其测量范围。

按研究方案使用合理的初始化、采样和随机化；禁止伪造测量。若研究密码协议，复现实验用的随机种子与协议安全所需的密码学随机性分别处理，不能因可复现要求把不安全随机源带入安全性主张。

## 安全与评价假设先于工具选择

按研究对象确定需要记录的假设，而不是给所有研究填入同一组默认值。

- 对 AI 安全研究，明确目标模型、攻击者能力、成功判据与评价方法；分别记录生成、攻击和评判所用工具的职责及限制。
- 对安全多方计算（MPC）和函数秘密共享（FSS），按适用范围明确安全参数、参与方、串谋条件、半诚实或恶意对手、预处理或可信设置等假设。声明的安全模型必须与证明、实现和实验对应。
- 效率比较应按任务区分离线/在线阶段、通信量、通信轮数及计算成本，记录网络和计时范围。不同安全假设或功能范围下的结果不能不加说明地直接比较。

上述内容是方向相关的检查维度，不是预设安全模型、工具清单或实验数值。具体选择及不适用项的理由保存在研究实例。

## 图表按表达与可核验性选择

统计图由实际数据生成，记录数据、变换和绘图来源。协议交互图及结构图优先保留可编辑、可核对的结构化或矢量来源，确保符号和流程与正文一致。

生成式图片可按需要用于概念插图，但不作为精确协议描述或实验结果的默认制作方式。明确示意图与证据图的性质，不指定模型或绘图供应方。

## 文稿内容与输出格式分别管理

先组织论证、证据和可编辑内容，再根据目标要求选择编辑与导出工具。LaTeX、Markdown、Word 等是可选格式，具体入口与产物由实例输出配置指定。

未选格式不阻止前期研究。已有工具只对其实际支持的格式负责；缺少适配时说明所需能力，在环境计划中安排验证，不宣称未实现的转换已经可用。编译成功只说明格式处理成功，不代替内容或投稿规范检查。
