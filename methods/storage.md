# 架构与存储约定

## 判定原则

**描述做事的方法，放通用方法；描述某个对象的事实、选择、参数或结果，放该对象的文件。** 通用方法可以规定调查、规划、配置、执行、验证和记录方式，也可以规定存储路径；不能把当前调查结果或某次选择写成通用要求。

同一个可变事实只设一个当前维护位置。引用方写明需要它的原因和路径，不复制其值。历史快照可以保存当时的副本，但必须带来源、时间和哈希，且不作为当前配置入口。

## 归属表

| 信息 | 当前维护位置 | 引用方式 |
| --- | --- | --- |
| 写作方法与判断标准 | 根目录方法文件 | 实例通过 `method_ref` 引用 |
| 工作区目录与默认环境标识 | `workspace.yaml` | 工具读取，不在其他配置重复写默认值 |
| 工具入口解释器 | `environment/launcher.json` | 启动脚本读取，profile 可通过空值继承 |
| 主机能力、已安装软件 | `environment/profiles/<profile>/inventory.json` | 环境计划与实例验证记录引用 |
| 环境运行参数、资源上限 | 同一 profile 的 `config.yaml` | 实例 `environment/selection.yaml` 选 profile；差异放 overrides |
| 环境配置计划和执行记录 | profile 的 `plan.md`、`changes.md`、验证文件 | 方法文件只指向这些记录 |
| 论文题目、目标、截止日期、语言 | `projects/<id>/project.yaml` | 构想、计划和正文引用；展示副本标明配置是准据 |
| 论文篇幅、引用规范、验收条件 | 实例 `docs/writing_requirements.yaml` 及官方规范文件 | 写作、评审、导出读取 |
| 论文所需的环境能力与专有调整 | 实例 `environment/` | 需求 → 选择 → 计划 → 变更 → 验证 |
| 数据、文献、代码、正文、结果 | 实例 `data/`、`docs/literature/`、`code/`、`paper/`、`results/` | 通过证据路径与定位引用 |
| 论文计划、进度、迭代 | 实例 `plans/`、`PROGRESS.md`、`state/`、`archive/` | 不写入共享方法或环境事实 |
| 原文、示例、空模板 | `references/original/`、`examples/`、`templates/` | 明确其性质，不自动转换为事实或默认要求 |

## 路径语义

根目录方法文件中未特别说明的管理路径相对工作区根目录。`workflow.yaml` 的 `expected_artifact` 相对论文实例根目录。实例 `project.yaml` 的 `method_ref` 相对实例根目录；实例环境选择通过 profile 标识在工作区 `environment_profiles` 路径下解析。`config.yaml` 的 runtime 路径相对工作区根目录；profile 的依赖与说明文件名相对 profile 目录。

每篇论文都引用共享方法与环境，不复制一份继续独立维护。实例专有覆盖只记录差异和原因。每次实验 manifest 保存环境引用、配置文件哈希与实际生效参数，以便配置后来变化时仍能追溯。迭代归档保存只读的引用快照。

## 变更传播

- 改机器或工具：更新对应环境调查、计划、配置与验证，评估引用它的实例。
- 改题目、论证或投稿要求：更新本实例相关文件，评估本篇计划及正文。
- 改通用方法：说明适用范围，验证工具和实例契约，记录版本；不从某个案例直接推导全局默认。
- 新增论文：从空模板生成独立目录，不继承其他论文的题目、预算覆盖、数据、结果或进度。
- 新增示例：只存示例目录。需要采用时作出显式选择并记录理由。
